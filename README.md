## Development Environment & Database Setup

This project uses **jOOQ** for type-safe SQL and **Liquibase** for database migrations. Since the generated jOOQ classes are derived from the database schema, they are not stored in the repository (excluded via `.gitignore`).

Every developer must generate these classes locally after cloning the project or when the database schema changes.

### 📋 Prerequisites
* **Java 21**
* **Maven 3.9+**
* **Docker (or OrbStack) & Docker Compose**

### 🚀 Getting Started

Follow these steps to sync your local environment with the current database schema:

1.  **Start the Database** Spin up the PostgreSQL container in the background:
    ```bash
    docker-compose up -d db
    ```

2.  **Run Database Migrations** Apply all Liquibase changelogs to your local instance:
    ```bash
    mvn liquibase:update
    ```

3.  **Generate jOOQ Sources** Scan the database schema and generate Java DSL classes:
    ```bash
    mvn generate-sources
    ```

### 🖥 IDE Integration (IntelliJ IDEA / VS Code)
After running the generation command, your IDE might still highlight jOOQ classes in red. To fix this:
1.  Right-click on the project root -> **Maven** -> **Reload Project**.
2.  If the folder `target/generated-sources/jooq` is not recognized, right-click it -> **Mark Directory as** -> **Generated Sources Root**.

---

### 🔄 Workflow: Adding Database Changes
When you need to modify the database (add a table or a column):
1.  Create a new XML changeset in `src/main/resources/db/changelog/v2.0/`.
2.  Include the new file in `changelog-master.xml`.
3.  Execute `mvn liquibase:update` followed by `mvn generate-sources`.
4.  Your Java code is now aware of the new schema changes!

## 🤖 AI assistant (Spring AI)

The application ships an in-app assistant built on [Spring AI](https://spring.io/projects/spring-ai).
It answers questions about events, prices, seat availability and the signed-in user's orders, and it
never changes data on its own.

### Switching it on

The assistant is **off by default**: without an API key the mutation answers with a short "not
configured" message, and the application starts without any network access. Enable it with
environment variables:

```bash
export OPENAI_API_KEY=sk-...       # OpenAI or OpenAI-compatible key
export AI_CHAT_MODEL=gpt-4o-mini   # optional, this is the default
```

`AI_CHAT_MODEL` and the temperature (`0.2`) live in `src/main/resources/application.yml`. To use
another provider, add its Spring AI starter and replace the API-key check in `AssistantService` (it
gates the assistant on `spring.ai.openai.api-key`).

Until a key is configured the mutation still works and answers
"The AI assistant is not switched on for this server yet. Please use the event search instead."

### GraphQL API

```graphql
mutation Ask {
  askAssistant(question: "Máte v Praze v květnu nějaký jazzový koncert?", conversationId: "3f1c9a54-...") {
    answer
    conversationId
  }
}
```

`conversationId` is generated by the client (one UUID per chat window). The server keeps the last 20
messages of a conversation in memory, keyed by the signed-in user **and** that id, so two users can
never share a conversation. The field is public: anonymous visitors can browse events, while tools
that read personal data answer "please sign in".

### What the bot can do

| Tool | Purpose |
| --- | --- |
| `search_activities` | full-text search (Elasticsearch) plus date/city/category filters, max 10 hits |
| `get_activity_details` | description, hall address, performers, ticket types, free seat count |
| `get_seat_availability` | free seats per row with ticket types and prices |
| `list_cities` | cities that currently have events |
| `list_categories` | event categories |
| `get_my_upcoming_orders` | tickets and totals of the signed-in user |
| `get_my_favorite_activities` | favourites of the signed-in user |

Tools are declared in `AssistantTools` with `@Tool`/`@ToolParam`; the system prompt in
`AssistantService` tells the model to answer only from tool output, never to invent ids or prices and
to hand payments back to the website UI.

### Deliberate limits (v1)

* **Read-only.** `checkout`, activity, hall and offer management are not exposed as tools, so a
  prompt injection cannot spend money or change the schedule.
* Tools never accept a user id; personal data always comes from `SecurityContextHolder`.
* Questions are limited to 2000 characters and conversation ids to 64; tool answers are truncated
  (10 events, 25 rows, 10 orders, 10 favourites).
* Chat memory is in-process (`InMemoryChatMemoryRepository`): it is lost on restart and does not
  scale horizontally. Swap it for a persistent chat-memory repository when you need either.
* There is no rate limit yet. If the public endpoint gets expensive, add a limiter or require
  authentication for `askAssistant`.

### Version note

Spring AI 2.x is the generation that supports Spring Boot 4; the project uses `spring-ai-bom:2.0.2`
(see `pom.xml`), which is built and tested against Spring Boot 4.1.x while the parent here is 4.0.2.
If you hit a `NoSuchMethodError` from Spring Framework during an assistant call, bump the
`spring-boot-starter-parent` version to 4.1.x - nothing else in the assistant depends on it.
